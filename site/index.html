DevPlane

An internal developer platform, built one layer at a time. Today it keeps a catalog of services, generates each one's starting project from a template, and pushes that project to a new GitHub repository. Deployments, monitoring, and AI-assisted operations come next.

Phase 1 is complete. Phase 2, deployment, is next.

Try the demo View the source on GitHub

What it does today

A service starts as an entry in the catalog and ends up as a repository you can clone and build. Each step is one action in its web UI, or one request to its REST API. You can walk through them in the demo.

  1. Register the service

    Give it a name, an owning team, and a lifecycle stage. Names are DNS-safe, so they still work later as repository and Kubernetes names.

    POST/api/v1/services

  2. Download its project

    DevPlane generates a Spring Boot (Java 21) REST API with PostgreSQL from the java-rest-api template, named after the service.

    GET/api/v1/services/{name}/project

  3. Create its repository

    DevPlane creates a GitHub repository, pushes the project as its first commit, and records the repository in the catalog.

    POST/api/v1/services/{name}/repository

What a generated project contains

A small, complete service: an example resource stored in PostgreSQL, a health check, OpenAPI docs, a Flyway migration, and tests that run against a real database in a container.

DevPlane's own build generates a project and runs that project's build, so a template change that breaks the generated code also breaks DevPlane's build.

Where it's going

The aim is a platform where a developer asks for something like "a Java REST API with PostgreSQL, deployed to staging", and DevPlane handles the repository, pipeline, deployment, and monitoring. It's built in four phases. Each one is a thin slice that works end to end, runs on a laptop, and costs nothing.

  1. Phase 1: Platform core

    Complete

    • Service catalog: services with an owner and a lifecycle stage
    • Platform API: versioned REST API with OpenAPI docs
    • Golden-path service template: Java REST API with PostgreSQL
    • Service creation workflow: generate a new service from the template
    • Repository provisioning: push the generated service to a new GitHub repository
    • Web UI for browsing the catalog and creating services
    • Public site: a splash page and a try-it demo on GitHub Pages

  2. Phase 2: Deployment

    Planned

    • Containerization: generated services include a Dockerfile
    • CI/CD: generated services include a GitHub Actions pipeline
    • Kubernetes deployment to a local kind cluster
    • Deployment history and status for each service
    • Stretch: cloud infrastructure with Infrastructure as Code (Terraform)

  3. Phase 3: Observability

    Planned

    • Metrics: generated services expose Prometheus metrics
    • Logs: generated services write structured JSON logs
    • Service health monitoring shown in the catalog
    • Stretch: Grafana dashboards and distributed tracing (OpenTelemetry)

  4. Phase 4: AI operations

    Planned

    • Deployment diagnostics: a tool-using agent that explains failed deployments
    • Human approval before any suggested fix is applied
    • MCP server exposing the catalog and workflows to AI assistants
    • Stretch: automated remediation for known failure types

How it's built

Stack
Java 21 and Spring Boot 4, PostgreSQL with Flyway migrations, server-rendered pages with Thymeleaf and htmx, and Gradle.
Specs before code
Every change starts as an OpenSpec proposal with specs, a design, and tasks, and is checked against those specs before it's archived. Read the specs
Tests against real things
Integration tests run against PostgreSQL in a container. GitHub is replaced by a small fake server, so the build needs no token.
$0 to run
Everything runs on a laptop: Docker for the database, kind for Kubernetes, and GitHub's free tier for repositories and CI.

Run it locally

You need JDK 21 and a running Docker runtime. DevPlane starts its own PostgreSQL database, and serves its API documentation at /swagger-ui.html.

The README covers creating a service and pushing it to GitHub.

git clone https://github.com/spollito/devplane.git
cd devplane
./gradlew bootRun
# then open http://localhost:8080
