# Proposal: Add the public site

## Why

DevPlane runs on `127.0.0.1` with no login, so nobody can see it without cloning the
repository and starting it with Docker. The people most likely to look at it, such as
reviewers and recruiters, won't do that. A public site explains what DevPlane does and
lets them try it in a browser. The look and content were already approved in
`docs/mockups/landing.html`, but until now the site was only a note in an archived
change.

Roadmap: adds and completes a new Phase 1 item, "Public site: a splash page and a
try-it demo on GitHub Pages". Phases are built in order, so it finishes before Phase 2
starts.

## What Changes

- A static site is published at `https://spollito.github.io/devplane/` from `main`, using
  GitHub Pages. It has no server and no secrets, and it loads nothing from other hosts.
- **Splash page**, from the approved mockup:
  - what DevPlane does today, the vision, how it's built, and how to run it
  - the drawing of DevPlane's layers, redrawn with the Interface layer as built
  - the README roadmap with each item's real state
  - a "Try the demo" action, and a link to the source
- **Try-it demo**, which runs entirely in the visitor's browser:
  - browse a sample catalog, and filter it by owner
  - register a service, using the same validation rules and messages as the real app
  - view a service's path from catalog entry to project to repository
  - unregister a service, and reset the demo to its sample data
  - "Download project" gives a real `orders-api.zip`, generated by DevPlane's own code
    when the site is built
  - "Create repository" is simulated, says so, and creates nothing
  - every screen says it's a demo with sample data, and that nothing leaves the browser
- **The site can't drift unnoticed.** The build fails when the site's roadmap differs from
  the README, or when the demo's validation rules differ from the real app's.
- `docs/ui-guidelines.md`'s Public site section covers the demo, and the README links to
  the site.
- `devplane.css` loads its fonts by relative path, so the same file works under
  `/devplane/` on Pages.

**Out of scope**

- Hosting the real application, or any server or database for the site
- Accounts, saving data anywhere but the visitor's browser, and analytics
- A custom domain
- Generating projects for arbitrary service names in the browser. The download is always
  the `orders-api` example, and the demo says so.
- Creating real GitHub repositories from the demo
- Paging in the demo. It lists every service, because its catalog stays small.
- Anything from Phase 2 onward

## Capabilities

### New Capabilities

- `public-site`: The public face of DevPlane on GitHub Pages: publishing it, the splash
  page, the in-browser demo, and the checks that keep both in step with the real app.

### Modified Capabilities

None. The application's behavior doesn't change. The stylesheet's font paths change, but
the fonts load the same way in the app.

## Impact

- **New files:**
  - `site/`: the splash page, its stylesheet, the demo's HTML and JavaScript, the demo's
    tests, and the drawing script
  - `.github/workflows/pages.yml`
- **Build:**
  - A `siteBuild` Gradle task assembles `build/site/` from `site/`, the app's stylesheet
    and fonts, and the generated zip. A small test-source class generates the zip through
    the real `ProjectArchiver`.
  - The Gradle `test` task gains drift checks.
- **CI:** the new workflow builds the site and runs the demo's tests on pull requests, and
  deploys only from `main`. It uses Node's built-in test runner, with no npm packages.
- **Repository settings:** Pages must be switched on once, with GitHub Actions as its
  source. That needs the owner, and it's outward-facing, so it's confirmed when it's done.
- **Dependencies:** none. No npm packages, no site generator, and no third-party scripts.
- **Depends on:** `harden-web-ui` should land first, so the site inherits its layout
  fixes.
- **Docs:** README.md (the roadmap item and a link to the site), docs/ui-guidelines.md,
  docs/architecture.md, and docs/mockups/README.md.
